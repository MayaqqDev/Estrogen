# Contributing
Heya! So you wanna contribute? There is a few rules you have to follow first! Thanks <3
## Formatting
There isn't a hard formatting guideline, though try to keep code not going past the wrap line. In general follow 
kotlin/java formatting rules and if you are unsure try to look at other code in the project as an example. A conventional
formatter is encouraged.
## Commit Convention
Recently, I have adpoted the [Conventional Commits](https://www.conventionalcommits.org) Convention, while not necessary,
if you get to the point, please do follow it. Additionally, try to split your commits into small, one change/feature commits,
I do not care if you submit 2 or 20 commits in a PR, though the commit amount should reflect the amount of changes *somewhat*.

### Examples

#### Do:

- `feat: Added power stick item`
- `chore(Gradle): cleaned up dependencies`
- `docs: add CONTRIBUTING.md`
- `ci: added gametests for Centrifuge`
- `fix(Compat): fixed Crash with Supplementaries (again)`

#### Don't:
- `fixed bug`
- `complete refractor`
- `add CONTRIBUTING.md`

These are not a requirement, but they sure as hell make commit navigation easier...

## Pull Request Convention
Similarly to commits, please split Pull Requests into ones dedicated to a singular goal. At least somewhat.

## Strict no-AI policy

Adapted and extended from [Zig's Policy](https://ziglang.org/code-of-conduct/#strict-no-llm-no-ai-policy).

Do not use AIs for any code, issues, patches/PRs, comments or assets (such as, but not limited to, images).

If you *have* been found to use AI in any submissions to the project you will be prohibited from contributing indefinitely.
